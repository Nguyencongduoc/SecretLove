## Changes, defects and test corrections

- Fixed the editor's obsolete “Sharing will be added in the next milestone” caption to reflect implemented publishing/read-only behavior. No new product feature or authorization change.
- Added combined gift E2E and pre-upgrade database fixture/assertions. Development-only jsqr independently decodes the downloaded QR; no new production dependency. See the [decoder documentation](https://github.com/cozmo/jsQR).
- Runner supplies fixture IDs for exact fault scope and a dedicated GIFT creator. This keeps the larger suite within existing Creator upload limits; thresholds/counters are neither raised nor cleared. Existing server-controlled isolated loopback recipient rate namespace remains restricted/tested.
- Earlier focused failures: Save assertion exceeded its five-second wait while the request remained pending; deletion incorrectly expected only 200 instead of the documented 202 for queued media. Corrected the test wait/status expectation.
- Earlier full run: the simulated clock was installed in the main recipient context and disrupted later animation/reload checks. Fixed by using an independent browser context with normal verification. [Playwright clocks apply across a browser context](https://playwright.dev/docs/api/class-clock). That in-flight run recorded 14 PASS/2 FAIL; the fresh final run recorded 16 PASS/0 FAIL.

Remaining confirmed implementation defects in tested scope: **none**. These results are bounded acceptance evidence, not a complete production security audit.

## NOT TESTED / security and release blockers

1. Real deployed HTTPS cookie/Origin/CSP/referrer/cache behavior, trusted Vercel IP-header boundary, multi-instance races/resource/egress/rate budgets, stalled downloads/cancellation and provider-wide outages. Local production-mode tests do not certify the deployed boundary.
2. Actual 30-minute server expiry over HTTP and suspension/resume on physical devices. Local SQL expiry plus simulated client teardown are independently tested, but cannot substitute for that live wait.
3. Safari/iOS/Android hardware audibility/volume/codec matrix, representative CBR/VBR/CRC/tag corpus, maximum-length reading and full keyboard-only journey. Slider keyboard interaction, responsive/reduced-motion layout and actual failed-WebGL fallback pass.
4. Scheduled cleanup delivery, entire queue drainage, live stale/orphan sweeps, outage retries and provider backup retention. The retained music test independently proves one detached synthetic object's physical removal per execution; no erasure-time SLA.
5. Real signup/confirmation/recovery SMTP and outstanding copied-proof recovery replay cases from Day 1 remain release gates. Admin-confirmed fixtures/admin-generated recovery links do not prove mail delivery.
6. Operator cleanup of 34 tracked synthetic Auth accounts (10 added in this integration task). IDs only are kept in ignored .test-fixtures.json; no existing account deletion. Completed tests delete their own letters through version-checked application APIs; physical media cleanup can remain queued. Earlier failed runs may have left synthetic drafts/media.

There is no newly detected unresolved authorization defect in the tested boundaries. Production release remains blocked on the unverified deployed/external security gates above. No deployment or next feature milestone was started.
